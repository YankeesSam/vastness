# Vastness agent OS

Token-cheap control plane. Do not load the architecture or requirements docs whole; grep the IDs (`VN-...`) the active task names.

## Paths

Project root is the directory that contains `agent/STATE.md`.

| File | Role | Load when |
|---|---|---|
| `agent/STATE.md` | machine state | every session |
| `agent/HANDOFF.md` | next-session brief | every session |
| `agent/PLAN.md` | task queue | start, plan, execute, inbox |
| `agent/DEFECTS.md` | open defects | start, execute, inbox |
| `agent/WORKINGLIST.md` | raw user inbox | inbox only |
| `agent/OPTIMIZATIONS.md` | tool ledger | optimize, start if stale |
| `agent/CONTEXT.md` | allowed-read list | execute |

Never dump these into the reply. Read, act, write back.

## Commands

| Utterance | Skill |
|---|---|
| start / continue / next / go | vastness-start |
| plan / roadmap | vastness-plan |
| execute / implement / TDD | vastness-execute |
| handoff / commit / push / done | vastness-handoff |
| optimize / tools | vastness-optimize |
| inbox / workinglist | vastness-inbox |

`start` already chains inbox, plan-if-stale, execute and handoff. Do not also load those SKILL.md files unless start says to.

Domain skills (loaded by execute, by the task's `files:`): vastness-ephemeris, vastness-scene. AGENTS.md maps areas to them.

## Hard rules

1. One active task per session (`STATE.active_task_id`).
2. TDD: a red test before production code.
3. ADRs in `docs/adr/` are law. Change one only through a task that names it.
4. Accuracy is tested, never eyeballed: positions are checked against Horizons samples (F2) with stated tolerances (VN-EPH-003, VN-EPH-008).
5. Read only `HANDOFF.read_next` plus the active PLAN line; grep IDs in docs/REQUIREMENTS.md instead of reading it whole.
6. After a completed or failed task, always run handoff.
7. Schema versions must match `references/schema.md`. Fix drift before coding.
8. Fixtures (docs/TESTBED.md):
   - F1 (`testdata/horizons`) recorded Horizons responses; F2 (`testdata/reference`) held-out samples; both small and committed.
   - F3 (`public/ephem`) is generated by `npm run ephem` and committed; never edit it by hand, never read it into context.
   - `.cache/horizons` is gitignored raw responses.
   Unit tests never touch the network (VN-DAT-007). Only `tools/ephem/record.ts`, `npm run ephem` and `ephem:refresh` call Horizons, politely (VN-DAT-002).
9. Product code (ADR-0001, ADR-0002):
   - src/core uses no DOM, React, three.js or Node API;
   - the app requests nothing but its own origin's static files;
   - no dynamic code;
   - outputs are deterministic;
   - runtime dependencies only as ADR-0001 lists.
10. Data and assets carry their source and licence in docs/DATA_SOURCES.md (ADR-0006). Mission text is written in our own words.
11. Never run `sudo`.
